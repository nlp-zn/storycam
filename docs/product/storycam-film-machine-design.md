# StoryCam Web Product Design

Date: 2026-04-25  
Status: Office-hours working design, not final spec  
Primary model assumption: Seedance 2.0 for first real video generation spike

## One-Liner

StoryCam 是一个 Web 端私人小剧场相机。用户输入一句私人念头，先得到剧本、人物资产和场景资产；确认后生成 1-3 个核心分镜组，每个分镜组可扩展成更多分镜图，并最终生成一个短视频片段。系统再建议把这些片段拼接成 10-15 秒的最终作品。

## Product Bet

用户不是来写专业分镜表的，也不是来管理工业短剧生产流水线的。用户想把一个私人的情绪、关系、回忆或幻想，变成一段像“私人记忆预告片”的视频。

第一版必须真的生成视频。纯剧本、纯海报、纯分镜图都不足以证明产品魔法。

但第一版也不能直接把用户扔进复杂编辑器。StoryCam 的核心体验应该像一个会拍戏的相机：

1. 用户说出想拍的东西。
2. 相机先理解故事、人和场景。
3. 用户确认“对，就是这个感觉”。
4. 相机生成少量核心分镜。
5. 用户可以在某个分镜上扩展细节。
6. 相机把每组分镜拍成一个短片段。
7. 系统建议拼成完整作品。

## Current MVP Decision

MVP 不再默认生成 5 个关键帧，也不默认一次主调用生成完整视频。

新的单位是 **核心分镜组**：

- MVP 默认生成 **1-3 个核心分镜图**。
- 每个核心分镜图代表一个可独立生成视频的片段组。
- 每个核心分镜图可以继续扩展出一组分镜图或镜头卡。
- 每个核心分镜组在 MVP 中对应 **1 次 Seedance 2.0 视频生成调用**。
- 最终作品由 1-3 个视频片段经系统建议拼接而成。

这能解决两个冲突：

- 如果默认 5 个关键帧，每帧都生成视频，成本和等待时间会膨胀。
- 如果 5 个关键帧只服务一次视频调用，用户点击扩展分镜的交互价值会被削弱。

核心分镜组让产品、成本、等待、确认和视频片段边界保持一致。

## Target Output

第一版完整生成一次作品时，系统至少产出：

- 剧本：用户能读懂的一段短剧本，不暴露专业九列分镜。
- 人物资产：1-3 个主要人物，每个包含角色设定、视觉参考、稳定描述。
- 场景资产：1-3 个主要场景，每个包含空间、氛围、时间、光线、关键物件。
- 分镜脚本：面向视频生成的轻量分镜，不直接展示为专业表格。
- 核心分镜图：1-3 张，代表 1-3 个片段组。
- 扩展分镜图：用户点开某个核心分镜后，可生成 3-8 个周边分镜卡。
- 视频片段：每个核心分镜组生成一个短视频片段。
- 拼接建议：系统建议片段顺序、转场、字幕、音乐和最终节奏。
- 最终作品：10-15 秒短视频。

## User Journey

### 1. 输入

用户输入一句话，例如：

> 我想把暗恋拍成韩剧雨夜

系统可以提供轻导演选项，但不要求用户先学习专业术语：

- 更遗憾一点
- 更甜一点
- 像私人回忆
- 像预告片
- 加旁白
- 少说话，多画面

### 2. 剧本和资产确认

输入后，用户先看到三类结果，而不是直接看到空的视频预览区：

1. **我的剧本**  
   一段能读懂的短剧本，说明故事发生了什么。

2. **人物资产**  
   主要人物卡。每张卡包含角色设定、外形、服装、情绪、关系和可复用视觉描述。

3. **场景资产**  
   主要场景卡。每张卡包含地点、时间、光线、氛围、关键物件和空间调度。

这个阶段的核心问题是：用户是否认可这个故事世界。

用户操作：

- 确认继续
- 改剧本
- 改人物
- 改场景
- 帮我决定

### 3. 生成分镜脚本和 1-3 个核心分镜图

用户确认剧本、人物和场景后，系统生成：

- 分镜脚本
- 1-3 个核心分镜图

核心分镜图不是最终视频的静态封面，而是视频片段的入口。

例子：

- 分镜组 A：便利店外，短信未发送
- 分镜组 B：玻璃反光里，两个人短暂重叠
- 分镜组 C：擦肩而过，伞柄留在画面边缘

如果故事很短，可以只生成 1 个核心分镜组。不要为了凑数量硬拆。

### 4. 扩展某个核心分镜

用户点击任意核心分镜图，进入分镜扩展画布。

交互参考：中心是被选中的核心分镜图，周围逐步生成扩展分镜卡。未生成的槽位显示 waiting/loading，让用户感觉“这一组镜头正在被导演出来”。

默认规则：

- 每个核心分镜组默认生成 3 个扩展分镜卡：进入、动作、反应。
- 最多展示 8 个槽位，用于补镜、反应镜头、空镜、转场、情绪加强或续写入口。
- 扩展分镜默认不等于独立视频调用。
- 扩展分镜是该核心分镜组的视频生成指导材料。

用户操作：

- 生成更多分镜
- 换一个角度
- 加强情绪
- 删除某张分镜
- 用这一组生成视频片段

### 5. 每个核心分镜组生成一个视频片段

用户确认某个核心分镜组后，系统把这组材料组装成一个 clip prompt packet：

- 剧本上下文
- 人物资产
- 场景资产
- 当前核心分镜图
- 扩展分镜图
- 镜头节奏
- 旁白字幕
- 音乐/声音方向
- 质量检查规则

然后调用 Seedance 2.0 生成该组视频片段。

MVP 调用数：

- 1 个核心分镜组 -> 1 个视频片段 -> 1 次主视频生成调用
- 2 个核心分镜组 -> 2 个视频片段 -> 2 次主视频生成调用
- 3 个核心分镜组 -> 3 个视频片段 -> 3 次主视频生成调用

扩展分镜图不自动增加调用数。只有当用户明确选择“把这个扩展分镜单独拍成一段”时，才进入高级或后续版本范围。

### 6. 片段确认

每个最初的核心分镜组生成一个片段后，用户看到 1-3 个候选片段。

用户可以：

- 确认片段
- 重拍某一段
- 换某段的情绪
- 调整字幕
- 删除某段
- 进入拼接

这个阶段的对象是“片段”，不是“单张图”。

### 7. 系统建议拼接为最终作品

当用户确认 1-3 个片段后，系统自动建议拼接：

- 片段顺序
- 片段时长
- 转场方式
- 字幕节奏
- 背景音乐
- 片尾留白

用户只需要确认或选择轻量选项：

- 更像预告片
- 更像私人回忆
- 更快一点
- 更慢一点
- 直接生成最终版

### 8. 结果页和继续拍

最终页展示：

- 最终视频
- 已使用的 1-3 个核心分镜组
- 每个片段的扩展分镜
- 继续拍入口
- 保存和分享

继续拍可以从三个层级发起：

- 从最终视频继续拍下一段
- 从某个片段继续拍下一段
- 从某个核心分镜或扩展分镜继续拍一个分支

默认主操作应该是继续拍，不是导出分镜表。

## Web Surface

第一版是 Web 端产品。设计不应该是移动端放大版。

建议使用四个紧凑界面，而不是一个万能界面：

1. **输入台**  
   左侧输入和轻导演选项，中间显示故事生成状态，右侧保留历史或草稿。

2. **资产确认台**  
   中央是剧本，下面或两侧是人物资产和场景资产。用户确认故事世界。

3. **分镜工作台**  
   中间展示 1-3 个核心分镜组，右侧展示分镜脚本和生成建议。用户可点击进入扩展画布。

4. **片段和拼接台**  
   展示 1-3 个已生成视频片段，系统建议拼接为最终作品。

界面不宜拆太多，否则失去“相机”的轻盈感。但也不应把剧本、资产、分镜、视频生成、拼接都塞在同一个画面里。

## Generation Logic

```text
用户输入
  -> 剧本
  -> 人物资产
  -> 场景资产
  -> 用户确认
  -> 分镜脚本
  -> 1-3 个核心分镜图
  -> 核心分镜扩展画布
  -> Clip Prompt Packet
  -> 每个核心分镜组生成一个视频片段
  -> 用户确认片段
  -> 系统建议拼接
  -> 最终作品
```

## Duration Logic

最终视频目标仍然是 10-15 秒。核心分镜组数量影响每段时长：

| 核心分镜组数量 | 建议片段时长 | 最终长度 |
| --- | --- | --- |
| 1 组 | 8-12 秒 | 8-12 秒 |
| 2 组 | 每组 5-7 秒 | 10-14 秒 |
| 3 组 | 每组 4-5 秒 | 12-15 秒 |

这意味着“3 个核心分镜组”不是 3 个完整短片，而是 3 个可确认、可重拍、可拼接的短片段。

## Seedance 2.0 Assumption

第一版主打模型选择：**Seedance 2.0**。

根据 ByteDance 官方发布信息，Seedance 2.0 支持 text/image/audio/video 四模态输入，支持多图、多视频、多音频混合参考，并强调 15 秒高质量多镜头音视频输出。StoryCam 应把它用于“分镜组到视频片段”的主生成，而不是把每张扩展分镜图都当成一次独立生成。

参考：

- [ByteDance Seedance 2.0 official launch](https://seed.bytedance.com/en/blog/seedance-2-0-official-launch)
- [Replicate: bytedance/seedance-2.0](https://replicate.com/bytedance/seedance-2.0)

## Shanyin Director Master Integration

Shanyin Director Master 的价值不是让普通用户填写专业表格，而是给 StoryCam 内部提供导演方法论。

映射关系：

| Shanyin 方法 | StoryCam 产品化表达 |
| --- | --- |
| 导演定调 | 轻导演选项和系统自动判断 |
| 节奏规划 | 核心分镜组数量和每段时长 |
| 剧本微调 | 剧本和资产确认阶段 |
| 九列分镜 | 内部 shot data，不直接暴露 |
| shot groups | 核心分镜组和扩展分镜卡 |
| Double Check | 片段生成前后的质量检查 |
| XLSX 输出 | 内部结构化数据和调试产物 |

StoryCam 应充分利用 `docs/research/shanyin-director-master/` 中的方法，但前台只展示用户能理解的材料：

- “我的剧本”
- “人物资产”
- “场景资产”
- “这一段会这样拍”
- “生成这一段视频”
- “拼成最终作品”

## Example: 暗恋韩剧雨夜

### 用户输入

> 我想把暗恋拍成韩剧雨夜

### 剧本

雨夜的便利店外，她反复删改一条告白短信。门铃响起，他从店里出来，两个人隔着玻璃反光短暂重叠，却没有真正看见彼此。擦肩而过后，镜头留在她没有递出去的伞柄和黑掉的手机屏幕。

### 人物资产

- 她：二十多岁，湿发，米色风衣，手里握着手机和透明伞，情绪克制。
- 他：二十多岁，深色外套，手里拿着便利店热饮，像是刚结束加班。

### 场景资产

- 雨夜便利店门口：冷白灯、湿漉漉街面、玻璃反光、门铃、雨声。

### 核心分镜组

1. 未发送短信  
   她站在便利店外，手机屏幕亮起，告白文字停在输入框里。

2. 玻璃反光  
   他从店里出来，两人的脸在玻璃反光里短暂重叠。

3. 擦肩而过  
   两个人错身，伞柄留在画面边缘，字幕出现。

### 片段生成

- 分镜组 1 生成 4-5 秒片段。
- 分镜组 2 生成 4-5 秒片段。
- 分镜组 3 生成 4-5 秒片段。
- 系统建议拼接为 12-15 秒最终作品。

## Open Questions

- 1-3 个核心分镜组由系统自动判断，还是用户在资产确认后选择数量？
- 如果只生成 1 个核心分镜组，是否也要展示扩展画布，还是直接生成视频片段？
- 扩展分镜卡的默认数量是 3 张还是 4 张更适合用户理解？
- 片段生成失败时，用户应该看到“重拍这一段”还是回到扩展分镜画布？
- 最终拼接是否第一版就需要真正调用拼接/剪辑能力，还是先用简单顺序合成？
- “主视觉海报”是否独立存在，还是由最强核心分镜图承担封面职责？
- 是否需要给高级用户暴露 Shanyin 风格的完整九列分镜调试视图？

## Success Criteria

MVP 成功不等于模型画面完美。MVP 成功是：

- 用户输入一句私人念头后，愿意确认系统生成的剧本、人物和场景。
- 用户能理解 1-3 个核心分镜组各自负责什么。
- 用户愿意点击核心分镜扩展更多分镜图。
- 用户能接受每个核心分镜组生成一个视频片段。
- 用户愿意把系统建议的片段拼成最终作品。
- 最终 10-15 秒视频有可分享的私人记忆感。

## Next Steps

1. 更新 Web 线框图，覆盖资产确认、分镜扩展、片段确认和拼接建议。
2. 做一个真实视频生成技术 spike：输入一句话，生成剧本、人物资产、场景资产、1-3 个核心分镜组，并用 Seedance 2.0 逐组生成片段。
3. 定义 clip prompt packet 的最小字段，并映射到 Shanyin 的内部九列分镜字段。
4. 做 5 个固定题材样例：暗恋雨夜、宠物冒险、童年回忆、小说角色、情绪短片。
5. 让 5 个朋友只测试一个问题：看到剧本、资产和核心分镜后，你是否愿意点“生成这一段视频”？

## Latest Product Correction

用户旅程已从“5 个关键帧 + 一次完整视频调用”修正为：

> 剧本 / 人物资产 / 场景资产 -> 确认 -> 分镜脚本 + 1-3 个核心分镜图 -> 每个核心分镜图可扩展 -> 每个核心分镜组生成一个视频片段 -> 用户确认片段 -> 系统建议拼接最终作品。

这是当前设计的最新基线。
